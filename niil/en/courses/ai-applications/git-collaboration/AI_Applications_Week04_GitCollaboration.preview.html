Exercise objective

Record edits with Commits, review changes in a PR, and check how Merge applies them to main. Use your own Repository for this exercise; Forks and PRs on a peer's Repository are optional.

For an external contributor's proposed changes and why each step is needed, see the explanation in the learning material.

1. Practice Git in your own workspace

After practicing Commits and Branches in a temporary Colab folder, follow the steps below for PRs and Merges on GitHub.

A. Baseline example · Read and run first

import tempfile, pathlib, subprocess
repo=pathlib.Path(tempfile.mkdtemp(prefix='course-git-'))
def git(*args):
    return subprocess.check_output(['git','-C',str(repo),*args],text=True,stderr=subprocess.STDOUT)
git('init','-b','main');git('config','user.name','Student Example');git('config','user.email','example@example.invalid')
(repo/'README.md').write_text('# Practice\nBaseline\n')
git('add','README.md');git('commit','-m','Add baseline')
git('switch','-c','practice-change')
(repo/'README.md').write_text('# Practice\nBaseline\nMy change\n')
print(git('diff'));git('add','README.md');git('commit','-m','Describe one change')
print(git('log','--oneline','--all','--graph'))

B. Hands-on activities

A Branch is a workflow recording changes separately. Here, create practice from the default Branch main and edit it. A Pull Request (PR) requests review before merging these changes into main; Merge actually combines the reviewed changes. Creating a PR alone does not change main.

  1. Practice change history in Colab: Edit one sentence in the local example and repeat git diff → add → commit → log yourself.

  2. Create a practice Repository on GitHub: Create a personal practice Repository with a README.

  3. Edit and Commit on a Branch: Create a new Branch practice, add what you learned this week to the README, and Commit.

  4. Review the PR and Merge: Open the Pull Request for practice → main, review the changes under Files changed, and Merge.

  5. Explain the changes: Explain the roles of the two Branches and the differences before and after Merge to a teaching assistant or peer.

  6. Record results: Record the Repository URL, Commit history, PR changes, and completed Merge screen in the Notebook.

At each stage, check which Branch records the changes. Compare main's content when the PR is opened and when it is Merged.

Optional exercise · Fork and Pull Request

Proceed when a peer has a public Repository for practicing together.

  1. Fork your peer's Repository and create a Branch in your Fork.
  2. Edit one explanatory sentence in README.md, then Commit and Push.
  3. Open a Pull Request to the original Repository and explain the reason for the change in one sentence.
  4. In a Text Cell in the notebook, record the Pull Request URL and the sentence you changed. Explain why you can propose changes without permission to Push directly to the original Repository.
