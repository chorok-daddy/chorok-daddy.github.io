01 좋은 응답의 기준

목표에 빨리 도달하지만 많이 흔들리는 응답과, 조금 느리지만 곧 정착하는 응답 중 어느 쪽이 좋을까요? 무엇을 기준으로 정해야 할까요?

설명
  • Rise Time·Settling Time·Overshoot는 서로 다른 특성 측정
  • 설계 목적에 맞는 지표와 허용 범위 지정

02 성능을 숫자로 표현하기

그래프를 보고 “빠르다”, “많이 흔들린다”고 말하는 대신 수치로 나타내면, 설계를 비교할 때 어떤 도움이 될까요?

설명
  • Rise Time·Settling Time·Overshoot로 응답의 서로 다른 특성을 측정할 수 있습니다.
  • 같은 기준으로 측정해야 비교가 가능합니다. Input, 최종값, 정착 범위 등을 함께 확인합니다.

진행 순서

  1. 기준 예제를 읽고 결과를 예상한 뒤 실행합니다.
  2. 각 항목의 직접 수행 문제를 풀고 조건·결과·이유를 기록합니다.
  3. 앞에서 비교한 세 조건을 정리하고 부족한 비교만 보충합니다.
  4. 실행 환경을 다시 시작하고 위에서부터 실행해 결과가 다시 나오는지 확인한 뒤 저장합니다.

1. 응답을 수치로 측정

Rise Time·Settling Time·Overshoot의 단위를 적고 그래프의 어느 부분을 측정한 것인지 표시하세요.

2. 최종값을 잘못 넣은 측정 수정

잘못된 최종값 1을 넣었을 때 지표가 달라지는 이유를 설명하세요. T의 DC Gain을 0.25로 바꾸어 같은 오류를 재현하고 수정하세요.

3. Pole·Zero 조건 변경

세 모델의 지표를 표로 비교하세요. Zero를 −2로 바꿀 때는 (s+2)/2, 추가 Pole을 −10으로 바꿀 때는 10/(s+10)을 기준 모델에 곱하세요. DC Gain을 유지한 상태에서 지표의 변화를 비교하세요.

제출·저장

코드, 실제 Output·그래프, 직접 작성한 해석을 포함하세요. 제출은 KLAS를 이용하며 기한은 학기 일정과 최신 공지를 확인합니다.
