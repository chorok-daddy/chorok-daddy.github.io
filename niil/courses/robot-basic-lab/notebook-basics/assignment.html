Notebook 기초

코드만 남기면 입력과 판단 근거를 잊기 쉽습니다. 작은 실험을 다시 읽고 확인할 수 있는 기록으로 만듭니다.

실습 전에

01 실행 결과만 남기면 어떤 조건을 알 수 없을까요?

설명

입력 데이터·변수의 의미·판단 기준이 없으면 같은 출력을 해석하기 어렵습니다.

02 코드가 바뀌었을 때 설명과 결과 중 무엇을 다시 확인해야 할까요?

설명

설명한 조건과 현재 코드, 마지막 실행 출력이 같은 실험을 가리키는지 확인합니다.

실습

실습용 노트북 미리보기실습용 노트북 다운로드

1. Markdown 실습 기록

시작 조건

주제는 가상의 거리 센서입니다. t=[0,1,2] s, 거리=[1.2,1.0,.9] m를 사용합니다.

진행 방법

  1. 제목 3단계와 실습 목적 2~3문장을 작성하세요.
  2. 시간·거리·단위를 포함한 표와 Δ거리/Δ시간 수식 한 개를 넣으세요.
  3. 관측 사실 두 개와 아직 판단할 수 없는 것 한 개를 구분하세요.

남길 결과

  • Markdown 셀 1개: 제목·표·수식·해석을 포함한 한 화면 분량.
기록 항목과 확인할 점
시간 [s]
거리 [m]
관찰

확인할 점

  • 표의 숫자와 설명에서 사용하는 단위가 같은가?
  • Markdown을 실행했을 때 수식과 표가 실제로 표시되는가?

2. 실행 기록과 예상 구분

시작 조건

같은 자료에서 0~1 s와 1~2 s의 평균 변화율을 구합니다.

진행 방법

  1. 계산 전 두 구간의 감소 속도를 예상해 문장으로 적으세요.
  2. 수식 대입과 계산 값을 기록하고 예상과 비교하세요.
  3. 인용한 원본 학습자료 링크 하나와 참고한 부분을 짧게 적으세요.

남길 결과

확인할 점

  • 단순 숫자 나열을 넘어 부호의 의미를 설명했는가?

3. 다른 데이터로 기록 재사용

시작 조건

새 거리 자료는 [1.2,1.25,1.3] m입니다. 시간은 동일합니다.

진행 방법

  1. 첫 기록의 형식을 복사하되 값·그래프 설명·해석을 새 데이터에 맞게 바꾸세요.
  2. 감소하던 자료와 증가하는 자료를 한 표에서 비교하세요.
  3. 수정하지 않고 남은 옛 숫자나 문장이 없는지 점검하세요.
