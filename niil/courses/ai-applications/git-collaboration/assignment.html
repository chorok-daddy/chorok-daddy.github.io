4주차 · 변경 이력을 남기며 협업하기

실습 전에

학습자료의 예시 복습: 외부 사용자의 수정 제안을 검토한 뒤 원본에 반영하는 상황을 떠올려 보세요. 이번에는 본인 저장소에서 각 단계의 역할을 확인합니다.

01 변경 내용을 남기는 이유

예시 상황 실행 안내를 고친 뒤 문제가 생겼다면, 무엇을 바꿨는지 어떻게 확인할 수 있을까요?

설명
  • 변경 내용을 설명과 함께 이력으로 남기는 작업을 Commit이라고 합니다.
  • 수정 전후 내용을 비교하면 빠진 준비 단계를 어디에 추가했는지, 다른 설명까지 바뀌었는지 확인할 수 있습니다.

02 여러 사람이 작업하는 방법

직접 수정 권한을 주지 않으면서도 다른 사람의 개선을 받아들이려면, 어떤 과정이 필요할까요?

설명
  • 기여자가 자신의 사본에서 변경을 만들고, 원본에 반영해 달라는 Pull Request(PR)를 보냅니다. 관리자는 변경 내용과 이유를 먼저 확인할 수 있습니다.
  • Fork·Branch에서 수정 → Commit → PR과 검토 → Merge 순서입니다. 변경을 제안할 기회와 원본에 반영할 권한을 분리합니다. 본인 저장소에서 연습할 때는 Fork를 생략합니다.

실습

먼저 변경 기록을 확인한 뒤 협업 절차를 연습합니다. Colab에서는 GitHub 로그인이나 권한 설정 없이 파일 수정·Commit·Branch의 관계를 확인합니다. 다음으로 GitHub 웹에서 본인 저장소를 만들고, 그 변경을 PR로 검토하고 Merge합니다. 앞 단계는 Git의 기록 방식, 뒤 단계는 GitHub의 검토·반영 과정을 익히기 위한 별도 연습입니다.

1. 내 작업 공간에서 Git 연습하기

  1. Colab에서 변경 이력 연습
    임시 Repository에서 파일 수정 전후와 Commit 이력을 비교합니다. 예제의 문장을 한 줄 수정하고 git diff → add → commit → log를 직접 반복하세요.

  2. GitHub에 연습 Repository 만들기
    PR·Merge를 연습할 저장소를 GitHub에 새로 만듭니다. README를 포함한 개인 연습 Repository를 만드세요. Colab의 임시 저장소를 업로드하는 단계는 아닙니다.

  3. Branch에서 수정하고 Commit하기
    새 Branch practice를 만들고 README에 이번 주 배운 내용을 추가하여 Commit하세요.

  4. PR 검토 후 Merge하기
    practice → main의 Pull Request를 열고 Files changed에서 변경을 검토한 뒤 Merge하세요.

  5. 변경 전후 설명하기
    조교 또는 동료에게 두 Branch의 역할과 Merge 전후 차이를 설명하세요.

  6. 결과 기록하기
    Repository URL, Commit 이력, PR 변경 내용과 Merge 완료 화면을 Notebook에 기록하세요.

제출·저장

수정한 내용, Commit·Pull Request·Merge 이력, 각 단계에서 한 일을 설명한 메모를 포함하세요. 제출은 KLAS를 이용하며 기한은 학기 일정과 최신 공지를 확인합니다.

GitHub 협업 결과는 저장소·Branch·PR의 변경 내용과 Merge 이력이 보이는 캡처로 남기세요. 인증 정보는 포함하지 않습니다. Notebook은 연습·기록용입니다.

실행 환경을 다시 시작하고 전체 코드를 위에서부터 실행한 뒤 저장하세요.

선택 실습

함께 연습할 동료의 공개 Repository가 있을 때 진행하세요.

  1. 동료의 Repository를 Fork하고, 본인의 Fork에서 Branch를 만드세요.
  2. README.md의 설명 한 문장을 고친 뒤 Commit하고 Push하세요.
  3. 원본 Repository를 대상으로 Pull Request를 열고, 변경 이유를 한 문장으로 적으세요.
  4. 노트북의 Text Cell에 Pull Request URL과 변경한 문장을 남기세요. 원본 Repository에 직접 Push할 권한이 없어도 변경을 제안할 수 있는 이유를 설명하세요.
