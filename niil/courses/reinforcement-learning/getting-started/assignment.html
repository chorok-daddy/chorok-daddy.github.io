종료 처리 한 줄이 학습 Target을 바꿀 수 있습니다. 환경 경계와 공정한 정책 평가부터 확인합니다.

실습 전에

01 시간 제한과 Terminal state는 같을까요?

설명

reset은 초기 관측과 info를, step은 새 관측·보상·terminated·truncated·info를 돌려줍니다. 실제 종료와 수집 시간 제한을 구분해야 학습 Target을 올바르게 계산할 수 있습니다.

02 Return이 비슷한 정책은 같은 방식으로 움직일까요?

설명

관측·행동·보상·다음 관측·종료 유형을 함께 저장합니다. Episode 경계와 환경 ID·seed가 있어야 전이의 의미를 다시 읽을 수 있습니다.

실행 조건

기준 Queue 예제는 NumPy로 실행합니다. 학습에 사용하지 않은 seed=100…104에서 정책을 비교합니다. 공개 환경 활동은 gymnasium·stable-baselines3를 사용합니다. 시각화할 때만 gymnasium[classic-control]이 필요합니다.

필요한 패키지가 없으면 Colab·Jupyter 코드 셀에서 %pip install control==0.10.2 gymnasium==1.3.0 stable-baselines3==2.9.2를 실행하세요.

적용 사례

장비·통신 자원의 처리량과 비용

합성 대기열에 매 시점 평균 2건이 도착합니다. 서비스 용량을 높이면 대기는 줄지만 에너지 비용이 늘어납니다.

관측·상태
대기 수 q=0…20. 관측 q/20.
행동
처리 용량 0·2·4 중 선택.
보상·제약
−(다음 대기 수 + 0.2×용량² + 10×유실 수). 100 step에서 시간 제한.
비교 기준
항상 용량 2, 대기 수에 따른 Threshold policy.
확인할 지표
평가 Return, 평균 대기 수, 평균 용량², 유실 수.

설비 점검 시점 선택

매번 점검하는 비용과 고장을 놓치는 비용의 균형을 연구 문제로 구성합니다.

관측·상태
최근 센서값·추세·마지막 점검 이후 시간. 실제 고장 상태와 관측의 차이 구분.
행동
계속 운전·점검·교체.
보상·제약
운전 이익−점검·교체·고장 비용.
비교 기준
주기 점검, 임계값 경보.
확인할 지표
가동률, 고장 수, 총 비용. 고장 Label 누출 여부 확인.

2. 공개 환경을 직접 읽고 기록하기

시작 조건

Gymnasium CartPole-v1을 사용합니다. Random policy와 각도·각속도의 간단한 Rule을 seed=100,101,102에서 비교합니다.

진행 방법

  1. observation_space·action_space·Episode 제한을 출력하고, 공식 문서에서 관측 4개 성분과 두 행동의 의미를 확인하세요.
  2. 두 정책을 같은 seed에서 실행하고 Return·길이·종료 유형을 기록하세요.
  3. 전이 기록을 NPZ로 저장하고 다시 읽으세요. 첫 전이와 Episode 경계를 찾아 관측 수·행동 수의 대응을 확인합니다.

남길 결과

  • 정책별 3행의 평가 표와 전이 예 1개.
  • 환경 ID·정책·seed·라이브러리 버전이 포함된 trace 파일 1개.

3. 본인의 연구 문제로 옮기기

시작 조건

앞의 실험을 바탕으로 Queue·Motor 또는 본인의 연구 문제 하나를 선택해, 실제 적용을 위한 실험을 설계합니다.

진행 방법

  1. 상태·관측·행동·보상·종료·시간 제한을 표 한 장으로 정의하세요. 각 변수의 단위와 실제로 얻을 수 있는 정보를 적습니다.
  2. 예상 전이 3개를 수치로 적어, 좋은 행동과 나쁜 행동의 보상이 의도에 맞는지 확인하세요.
  3. 규칙 기반 비교 기준 한 개, 평가 조건 한 개, 가장 우려되는 실패 사례 한 개를 정하세요. 필요한 실측 자료나 Simulator도 적습니다.
