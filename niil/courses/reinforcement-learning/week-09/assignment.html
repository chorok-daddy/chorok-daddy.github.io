Isaac Lab과 Robot Simulation

대학원 · 연구 적용 실습

새 Simulator의 예제를 실행하는 데서 멈추지 않고, 내 연구 Task에서 바꿔야 할 관측·행동·물리를 찾습니다.

실습 전에

01 Task·Physics·Renderer·RL library는 같은 역할일까요?

설명

Task는 관측·행동·Reward·Reset·Termination을 정의합니다. Physics backend는 물리 계산을, Renderer는 영상 생성을, RL library는 정책 학습을 담당합니다.

02 정책 제어 주기와 물리 Step이 다르면 무엇을 맞춰야 할까요?

설명

물리 Step과 정책의 제어 주기는 같지 않을 수 있습니다. Action scale·Joint 단위·Control decimation을 맞춰야 다른 Simulator나 로봇으로 정책을 옮길 수 있습니다.

실행 조건

  • CPU 경로: Gymnasium·NumPy·Matplotlib.
  • 공식 SO-101 튜토리얼: Python 3.12·uv·Git LFS, Linux/Windows + NVIDIA GPU.
  • GPU 환경: 수업 전 점검. 개인 장비 우선, 공용 환경으로 보완.
  • Jetson 확장: Edge 추론·지연 측정.

2. 환경 온보딩: 실행 또는 Transition 분석

시작 조건

GPU 환경: 준비된 Linux/Windows NVIDIA 환경에서 공식 Quickstart의 Task 목록→Zero/Random agent→학습→Play 순으로 진행합니다. CPU 환경: 같은 시간에 CartPole Transition·정책 비교와 Task 설정 대응을 완성합니다.

진행 방법

  1. GPU 환경이 준비되어 있으면 공식 문서의 현재 버전에 맞춰 Cartpole Task를 실행하고 Task ID·backend·seed·실행 명령을 기록하세요.
  2. GPU 환경이 없으면 제공된 CPU 코드에서 Random과 Rule의 궤적을 비교하고 종료 원인을 찾으세요.
  3. 선택 경로에서 관측·행동·종료 규칙 중 한 항목을 바꾸려면 어느 설정을 수정할지 찾으세요.
