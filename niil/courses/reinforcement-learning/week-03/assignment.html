DQN

대학원 · 연구 적용 실습

상태가 늘어날 때 Q-table을 Neural Network으로 바꿔도 정책이 실제로 좋아지는지 검증합니다.

실습 전에

01 Replay와 Target Network는 각각 무엇을 바꿀까요?

설명

DQN은 Q-table을 Neural Network으로 바꿉니다. Replay는 저장된 경험을 다시 사용하고 Target Network는 Target을 만드는 Parameter의 갱신을 분리합니다.

02 다른 환경의 Return을 직접 비교할 수 있을까요?

설명

Policy 이름만 맞추지 말고 Buffer·학습 시작·Target 갱신·입력 Normalization·탐색 일정을 대응시킵니다. 다른 환경의 Return은 같은 성능 단위가 아닙니다.

실행 조건

기준 Queue 예제는 NumPy로 실행합니다. 학습에 사용하지 않은 seed=100…104에서 정책을 비교합니다. PyTorch가 필요합니다. 짧은 합성 실험이며 학습 성능을 보장하는 설정은 아닙니다. 공개 환경 활동은 gymnasium·stable-baselines3를 사용합니다. 시각화할 때만 gymnasium[classic-control]이 필요합니다.

필요한 패키지가 없으면 Colab·Jupyter 코드 셀에서 %pip install control==0.10.2 gymnasium==1.3.0 stable-baselines3==2.9.2를 실행하세요.

1. 동일한 작은 문제의 DQN

시작 조건

Queue, 네트워크 1→32→3, Adam lr=.001, γ=.95\gamma=.95, Replay 3000, Batch 32, 1800 Transition을 사용합니다. Q-table 대신 함수 근사가 필요한 이유를 실제 정책으로 확인합니다.

진행 방법

  1. 먼저 Queue의 규칙 정책 성능을 확인한 뒤 제공된 학습 함수를 실행하세요.
  2. 학습 Loss와 q=0q=0…20의 선택 행동을 그리세요.
  3. 학습에 쓰지 않은 seed=100…104에서 Return·대기·비용·유실을 평가하세요.

2. 공개 DQN 구현으로 옮기기

시작 조건

SB3 DQN, CartPole-v1, 2048 Transition입니다. 앞의 Queue 결과와 점수를 직접 비교하지 않고, 같은 환경의 Random·Rule과 비교합니다.

진행 방법

  1. 공개 DQN의 Policy·Replay 크기·Target 갱신 주기·학습 시작 시점을 앞의 구현과 대응시키세요.
  2. 제공된 짧은 학습을 실행하고 seed=100…102에서 결정적으로 평가하세요.
  3. 학습 정책과 Random·Rule의 Episode 길이·Return을 비교하고, 학습량이 충분한지 판단할 근거를 적으세요.

3. 본인의 연구 문제로 옮기기

시작 조건

앞의 실험을 바탕으로 Queue·Motor 또는 본인의 연구 문제 하나를 선택해, 실제 적용을 위한 실험을 설계합니다.

진행 방법

  1. State·Observation·Action·Reward·종료·시간 제한을 표 한 장으로 정의하세요. 각 변수의 단위와 실제로 얻을 수 있는 정보를 적습니다.
  2. 예상 Transition 3개를 수치로 적어, 좋은 행동과 나쁜 행동의 보상이 의도에 맞는지 확인하세요.
  3. 규칙 기반 비교 기준 한 개, 평가 조건 한 개, 가장 우려되는 실패 사례 한 개를 정하세요. 필요한 실측 자료나 Simulator도 적습니다.

남길 결과

  • MDP 설계 표, Transition 예 3개, 비교 실험 계획.
  • 실제 연구 자료가 없으면 적용 사례의 합성 조건으로 설계합니다.
