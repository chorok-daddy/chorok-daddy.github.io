시험 형식과 답안 작성 예시

잘못된 API 요청 구분 · 기말시험 · 예시 2

이 자료는 시험 형식과 답안 작성 수준을 보여주는 예시이며, 예상문제가 아닙니다. 시험 준비는 공지된 출제 범위를 기준으로 하세요.

문제 상황

device는 필수 문자열이고 start는 정수인 FastAPI 경로입니다. 정상 형식이지만 없는 장치는 빈 목록을 반환한다고 정했습니다.

이해하고 적용할 내용

  • 요청 형식 검증·정상 조회·경로 오류를 구분하기
  • 오류를 감춘 성공 응답과 명확한 오류 응답의 차이를 설명하기

제공 참고자료

요청 규약
GET /readings. device: 필수 문자열, start: 필수 정수입니다.
상태 코드
200: 정상 처리. 422: 요청 파라미터 검증 실패. 404: 등록되지 않은 경로입니다.
빈 결과
존재하지 않는 장치도 형식이 올바르면 200과 []를 반환합니다.
검증
필수 파라미터 누락 또는 정수로 변환할 수 없는 start는 검증 실패입니다.
원문 문서
  • FastAPI 요청 검증
/readings?device=a&start=abc
/readings?device=missing&start=0

문항

  1. 제시된 두 요청의 상태 코드와 결과를 각각 쓰세요.
  2. /readings?start=0과 /unknown?device=a&start=0의 결과를 구분하세요.
  3. 첫 요청의 start만 0으로 고치면 어떤 오류가 해결되는지 쓰세요. 실제 조회값까지 확정할 수 있는지도 설명하세요.
  4. 모든 실패를 200과 []로 돌려주면 사용자가 무엇을 구분할 수 없게 되는지 설명하세요.
답안 작성 예시
  1. start=abc는 정수 검증에 실패해 422입니다. device=missing&start=0은 올바른 형식이므로 200과 []입니다.
  2. 첫 요청은 필수 device 누락으로 422, 둘째는 등록되지 않은 경로로 404입니다.
  3. 정수 형식 검증 오류가 해결됩니다. 조회 결과는 장치 a의 저장 자료에 따라 달라지므로 자료 없이 값까지 확정할 수는 없습니다.
  4. 올바른 조회의 빈 결과와 파라미터 오류·잘못된 경로가 같은 응답으로 보입니다. 클라이언트가 요청을 고칠지 빈 결과로 처리할지 판단하기 어렵습니다.
