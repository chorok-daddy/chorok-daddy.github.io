GitHub 협업

여러 사람이 같은 파일을 바꿀 때, 변경 내용을 잃지 않고 합치는 과정을 안전한 로컬 예제로 익힙니다.

실습 전에

01 Commit과 Branch는 무엇을 보관할까요?

설명

Commit은 변경 이력의 한 지점, Branch는 그 이력을 가리키는 이름입니다.

02 같은 줄을 다르게 수정하면 왜 자동 Merge가 어려울까요?

설명

서로 다른 의도를 Git이 결정할 수 없으므로 사람이 원하는 최종 내용을 정해야 합니다.

실행 조건

기준 실습은 임시 Local Git 저장소를 사용합니다. GitHub 계정이나 원격 저장소 연결 없이 변경·Branch·Merge를 확인할 수 있습니다.

실습

실습용 노트북 미리보기실습용 노트북 다운로드

1. 한 파일의 변경 추적

시작 조건

코드가 만든 임시 저장소의 README.md에서 Condition: baseline을 Condition: test로 바꿉니다.

진행 방법

  1. 기준 Commit을 확인한 뒤 문장 한 줄만 수정하세요.
  2. git diff와 git status를 확인하고 변경 전후를 기록하세요.
  3. 변경을 Commit한 뒤 직전 Commit과의 차이를 다시 확인하세요.

2. Branch에서 실험 조건 분리

시작 조건

같은 저장소에 experiment Branch를 만들고 README.md에 Rate: 10 Hz를 추가합니다.

진행 방법

  1. experiment에서 Commit한 뒤 main으로 돌아가 파일 내용을 비교하세요.
  2. 두 Branch의 이력을 log --oneline --all --graph로 확인하세요.
  3. main에 Merge한 후 파일과 이력에 무엇이 남는지 적으세요.

3. 충돌을 재현하고 해결

시작 조건

main과 experiment에서 같은 Condition 줄을 서로 다른 값으로 수정해 각각 Commit합니다.

진행 방법

  1. Merge를 시도하고 충돌 표시가 생긴 파일을 보관하세요.
  2. 선택한 최종 조건을 한 줄로 정리해 충돌을 해결하고 Commit하세요.
  3. 서로 다른 줄을 수정했을 때와 같은 줄을 수정했을 때의 차이를 설명하세요.
